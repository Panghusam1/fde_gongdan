# 第一天第 7 课：数据库搭建第一批——权限与规范型号

## 1. 本批真正建出的东西

```text
用户 users
  │
  └── 厂区成员关系 factory_memberships ── 厂区 factories
                                              │
                                              └── 现场设备 equipment
                                                        │
                                                        └── 规范型号 equipment_models
                                                                  │
                                                                  └── 产品系列 product_families
```

本批新增四张表，并改造一张表：

| 表 | 保存什么 | 不保存什么 |
|---|---|---|
| `users` | 外部身份编号、显示名称、是否启用 | 密码、厂区角色 |
| `factory_memberships` | 某用户在某厂区具有什么角色 | 用户个人资料、工单内容 |
| `product_families` | 厂商和标准产品系列，例如 Schneider Electric + ATV320 | 现场资产编号 |
| `equipment_models` | 某系列下的具体型号，例如 ATV320U15N4C | 设备安装在哪个厂区 |
| `equipment` | 厂区中的具体设备及其规范型号 | 重复维护的正式厂商、系列和型号文字 |

## 2. 为什么角色不放在用户表

如果在用户表写：

```text
张工.user_type = engineer
```

系统无法表达“张工在苏州厂是工程师，在无锡厂只是操作员”。

把角色放到成员关系后可以表达：

```text
张工 + 苏州厂 + engineer
张工 + 无锡厂 + operator
```

同一用户在同一厂区的同一角色由唯一约束保证不能重复。

当前允许四种角色：

- `operator`：现场操作员；
- `engineer`：工程师；
- `supervisor`：主管；
- `admin`：管理员。

这是第一周业务集合，不代表所有工厂永远只有四种角色。角色发生正式变化时要通过数据库迁移修改并重新测试。

## 3. 为什么用户表不保存密码

本项目只保存 `external_subject`，也就是外部身份系统给用户的稳定编号。

原因：

- 业务数据库负责“这个身份能访问哪个厂区”；
- 登录系统负责密码、多因素验证和账号恢复；
- 两种职责分开，项目不自行发明一套不安全的密码系统。

外部身份编号有唯一约束，防止同一登录身份对应两个业务用户。

## 4. 为什么要拆产品系列和具体型号

`ATV320` 是产品系列，`ATV320U15N4C` 是该系列下的一个具体型号。它们不是同一层级。

拆开以后：

- 系列级手册可以关联 `ATV320`；
- 只适用某型号的资料可以关联 `ATV320U15N4C`；
- 现场设备只保存一个规范型号编号；
- 检索时可以先按系列过滤，再按具体型号收紧；
- 不会因为每台设备重复输入厂商名称而产生大量不一致文字。

厂商、系列和型号的判重不区分大小写，因此 `ATV320` 与 `atv320` 不能被登记成两个标准系列。

## 5. 旧设备数据如何升级

迁移不是直接删除原来的三个文字字段，而是执行：

1. 从旧设备记录中汇总厂商与产品系列；
2. 建立或复用规范产品系列；
3. 汇总并建立具体型号；
4. 给每台旧设备回填 `equipment_model_id`；
5. 确认所有设备都有规范型号后，才把该字段设为非空；
6. 原文字段改名为 `raw_manufacturer`、`raw_product_family`、`raw_model_code`，保留追溯依据；
7. 新设备只需要填写规范型号，不再重复填写三段正式文字。

升级测试会先用旧结构插入一台设备，再单独执行新迁移，并核对设备编号、原始文字和规范型号都没有丢失。

## 6. 为什么建立这些索引

- `factory_memberships(user_id, is_active, factory_id)`：支持按用户查找可访问厂区，也为用户外键提供索引。
- 产品系列和具体型号的唯一索引：同时用于大小写无关判重和按系列定位型号。
- `equipment(equipment_model_id)`：支持从规范型号反查设备，也避免处理型号外键时扫描整张设备表。

索引来自已知查询和外键，不因为“看起来专业”而提前堆积。

## 7. 已被自动验证的规则

| 规则 | 测试证明什么 |
|---|---|
| R15 | 同一个外部身份不能创建两个用户 |
| R16 | 成员关系不能引用不存在的用户或厂区 |
| R17 | 非法厂区角色会被数据库拒绝 |
| R18 | 同一角色不能重复授权 |
| R19 | 同一厂商和系列大小写不同也不能重复登记 |
| R20 | 同一系列的具体型号大小写不同也不能重复登记 |
| R21 | 设备不能引用不存在的规范型号 |
| R22 | 新设备只填写规范型号即可建立完整关系 |
| R23 | 已有旧设备在升级时会保留并自动关联规范型号 |
