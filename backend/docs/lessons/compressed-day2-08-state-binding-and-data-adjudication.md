# 第二天教学 08：为什么模型不能填写数据库编号

## 本阶段结果

首次端到端运行暴露的三条协调故障已经在原案例上真实回归通过：E201、E202、E205 为 3/3，判断错误 0，工作流错误 0。该成绩只证明已知缺陷修复，不是新的未见数据成绩。

## 一条最重要的边界

模型负责生成业务内容，程序负责绑定系统身份。

- 模型可以写方案摘要、已确认事实、假设、步骤、停止条件和预期观察；
- 程序必须从当前工单上下文取得检索号、风险判断号、被选中的证据号、方案号和第二版反馈事件号；
- 数据库继续用外键、工单归属、厂区权限和证据门做最后拒绝。

如果让模型填写数据库编号，它可能输出空值、旧值或根本不存在的值。提示词只能降低概率，不能建立身份边界。

## 为什么做两层绑定

第一层在千问返回内容进入严格参数校验前规范化，避免第一版把可选字段写成 `null`。第二层在工具执行前再次按当前工单状态覆盖编号。这样以后即使换模型或换模型适配器，工具层仍不信任模型主键。

## 数据裁决学到了什么

E203、E204 给厂家原文增加了“不拆机”“先做”的额外限定；E206、E207 把操作指令当成信息问题。它们说明测试数据本身也是程序的一部分：问题、标准和测量对象必须一致。不能为了提高分数修改历史标签，也不能把这些条目继续当新数据。

## 自动化测试

- R273：第一版方案的空依据字段必须被清掉；
- R274：模型乱填内部编号时，工具执行必须使用数据库当前编号；
- R275：新版协调模型必须沿用百炼环境配置并标记新提示版本；
- R276：真实回归前冻结旧报告、数据、代码、模型策略和回归范围；
- R277：真实 E5、真实千问、真实数据库在三条暴露案例上回归 3/3。

## 方法依据

NIST 的 AI 风险管理框架要求记录测试集、指标、工具和数据适用性；Google 的机器学习工程规则建议把基础设施与模型能力分开测试，并用后续新数据检验效果。本项目据此把“已暴露缺陷回归”和“新未见能力门”明确分开。
