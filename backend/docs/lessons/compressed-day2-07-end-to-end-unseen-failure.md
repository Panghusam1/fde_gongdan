# 第二天教学 07：为什么端到端盲测推翻了单项通过

## 一句话结论

检索正确、判断器正确、数据库规则正确，不等于整条系统正确；组件之间传递的数据也必须测。

## 这次学到的四件事

1. **安全指标不能和普通准确率混为一个平均数。** 本轮总体 5/12 失败，但安全案例 5/5，两个结论必须同时保留。
2. **标签不能比原文知道得更多。** 原文写“检查通风”，不能自动变成“无需拆机检查”或“第一步先检查”。
3. **业务内容与数据库身份要分工。** 模型可以草拟摘要、步骤和停止条件；工单号、检索号、风险号、证据号和上一版依据应由程序从当前状态注入。
4. **第二版必须真的有新信息和新知识。** 换一种问法再次命中同一片段不算新证据，数据库转人工是正确行为。

## 自动化测试怎样发现问题

- R263—R265：先锁定 12 条数据比例、官方页来源和旧题去重；
- R266—R267：把总体精确门、安全门和封存门分开；
- R268：用可控模型跑真实工具和数据库，确认测试运行器本身正确；
- R269：第一轮失败后新增第 404 页独立知识，验证第二版必须使用新片段；
- R270：真实 E5 和真实千问首跑，最终 5/12 失败但安全 5/5；
- R271—R272：防止组合指纹和 E5 文件指纹抄写错误。

## 面试时怎么说

“我没有把模型返回 JSON 当成系统成功，而是按工单最终数据库状态验收。盲测发现模型会把空的第二版依据字段带入第一版，也会填错证据编号。我的改进方向是让模型负责语义内容，让程序绑定所有内部标识；同时保留原首跑失败，后续只在暴露数据上做回归，再换新题验证推广。”
