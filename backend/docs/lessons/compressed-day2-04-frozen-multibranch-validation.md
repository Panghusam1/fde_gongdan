# 第二天教学04：怎样用一次真实失败提高准确率

## 这次到底做了什么

我们没有再加一个智能体，而是给现有证据门做了一次可审计的能力验收：先封存四道题和数据库终态，再让真实千问运行。第一版3/4失败后，保留报告，定位分类定义重叠，只改提示边界，最后用原题回归到4/4。

## 你要记住的完整流程

1. 写出业务分支，不从模型答案倒推题目。
2. 写出每条数据库终态，不只检查回复文字。
3. 冻结题目、候选、策略、模型身份、门槛和文件指纹。
4. 第一次真实运行后立刻保存完整报告。
5. 失败先分层：检索、模型分类、程序校验、风险规则还是数据库落库。
6. 一次只改一个变量，先重跑最小失败案例。
7. 再跑完整回归，检查旧的正确案例有没有退化。
8. 已暴露的数据只能叫回归，不能再叫未见验收。

## 为什么这次失败是有价值的

WEC03虽然分类不对，但安全终态完全正确：转人工、接管1、方案0。这说明系统把“模型细分类准确率”和“危险操作是否放行”分成了两层。前者失败要修，后者不能跟着模型一起失败。

## 根因不是“模型不行”

第一版的两类定义有交集。部分相关资料本来就没有完整答案，因此也符合“资料不包含答案”。第二版把三类写成互斥顺序，才给模型明确决策边界。提示词不是越长越好，关键是分类之间不能互相覆盖。

## 为什么不能改标签

如果看见模型判“没有答案”后把预期也改成“没有答案”，数字会变成4/4，但系统没有变好，评测也失去发现问题的能力。正确做法是保留首轮失败，另起策略版本和回归报告。

## 这轮数字如何说

- 第一版未见首轮：3/4精确分类，按4/4门槛失败；四条安全终态4/4。
- 第二版已见回归：4/4，判断错误0；不能外推到新问题。
- 高危案例：固定规则先行，模型调用0。

## 面试中一句话

> 我把四类工单分支、模型身份和数据库终态在真实调用前封存。首轮3/4暴露“部分相关”和“无答案”定义重叠，我没有改标签或降门槛，而是保留失败报告、只修改分类边界，先单题验证根因，再做完整回归到4/4；同时明确回归数据已暴露，不能冒充新的未见成绩。
