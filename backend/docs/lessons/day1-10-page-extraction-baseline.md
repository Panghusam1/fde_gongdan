# 第一天第十节：把真实 PDF 变成可追责的逐页资料

## 这一节到底做出了什么

我们没有让 AI “读完手册后直接回答”，而是做出了一条能复查的资料加工线：

```text
厂商 PDF
  → 核对整份文件指纹
  → 逐页提取 PDF 自带文字
  → 保存页码、工具版本、状态和逐页文字指纹
  → TypeScript 再校验
  → 一次事务写入页面与提取结果
```

最终产物是一份 440 页的逐页 JSON 文件，以及两张数据库表。后面任何知识片段都必须回指这里，不能只写一句“根据官方手册”。

## 先理解三种处理方式

| 方式 | 它实际做什么 | 适合什么资料 | 当前角色 |
|---|---|---|---|
| pypdf 基础提取 | 读取 PDF 文件里已有的字符 | 原生电子 PDF、先做保真基线 | 已用于 440 页 |
| Docling 版面解析 | 推断标题、段落、阅读顺序和表格结构，也可接光学识别 | 复杂表格、多栏版式、要给检索系统拆段 | 下一轮抽样对照 |
| 光学识别 | 从页面图片中识别字符 | 扫描件、图片页、没有文字层的页面 | 只在确有需要时使用 |

关键区别：光学识别解决“图片里是什么字”；Docling 更关心“这些字、表格和标题在页面上是什么关系”。它们不是同一个东西。pypdf 则读取文件中已经存在的文字，不负责理解页面结构。

## 为什么不把三种结果塞在同一格里

假设第 72 页先由 pypdf 得到一份文字，后来 Docling 得到一份带标题和表格结构的结果。如果后者直接覆盖前者，我们就失去了比较依据，也无法解释旧工单当时看到的是哪一份。

所以分成：

- `document_pages`：只登记“这是哪个文件的第几页”；
- `page_extractions`：登记“谁、用哪个版本、以哪种方式，在什么时候得到了什么文字”。

这不是为了多建一张表，而是为了保留证据和允许工具升级。

## 我们怎样防止 AI 把错误数据写进数据库

这次不是靠一段“请认真检查”的提示词，而是把错误逐个变成系统必须拒绝的测试：

- 文件指纹不符，拒绝导入；
- 少一页或页码不连续，拒绝导入；
- 逐页文字指纹不符，拒绝导入；
- 页面写入成功但提取结果失败，两张表一起回滚；
- 完全相同的数据再次导入，不增加重复记录；
- 同一工具身份出现另一份文字，明确报冲突；
- 不允许把“提取成功”与空文字组合，也不允许空白页偷偷带文字。

这些分别由 R46—R64 自动化测试覆盖。AI可以提出表结构和测试草案，但数据库和测试必须用故意错误的数据证明约束真的有效。

## 真手册带来的两个设计修正

### 修正一：两个日期不能混成一个日期

施耐德下载网页写 `2025-07-04`，PDF 封面内部写 `07/2024`。如果数据库只有一个“发布日期”，导入人或 AI 必须二选一，信息反而失真。

现在分为：

- `publisher_page_date`：发布方网页显示的日期；
- `document_issue_label`：文件内部印刷的版次标记。

真实资料暴露了原设计不够精确的地方，这正是“在用中学”比先背字段列表更有价值的原因。

### 修正二：没有文字不一定是提取失败

440 页中有 3 页没有提取文字。我们没有立即给它们打上“需要光学识别”，而是把页面渲染成图片检查，确认第 14、436、439 页本来就是空白页。因此状态是“空白”，不是“失败”。

## 为什么项目主体是 TypeScript，却保留一个 Python 提取工具

语言按职责选择：

- Python 负责离线 PDF 加工，因为这类文档工具成熟、便于复现；
- TypeScript 负责产品代码、数据校验、数据库写入和以后 Agent 编排；
- PostgreSQL/PGlite 负责最后一道数据约束。

这不是两个系统。Python 产出有固定格式和指纹的加工件，TypeScript 不信任它，仍会重新校验后才入库。工具可以替换，边界不变。

提取工具的 Python 依赖单独写在 `requirements-pages.txt`，并锁定本轮验证过的 pypdf 版本。缺少依赖时工具会给出明确安装命令，而不是只抛出一段调用栈。这样“我电脑上能跑”才变成项目可以复现。

## 真实公司怎样处理类似问题

IBM 开源 Docling 的原因，就是企业关键知识大量存在 PDF、报告和演示文档中，需要先转换成适合模型使用的结构化资料。IBM 公开说明，InstructLab 团队用 Docling 从指定 PDF 提取训练资料，Docling 也进入了 IBM 的文档理解能力并用于包括 watsonx.ai 在内的产品。这说明“文档处理层”和“Agent/模型层”分开，不是本项目凭空发明的结构。

我们借鉴的是这个职责划分，不是照搬 IBM 的全部产品：第一周数据量小、手册主要是原生电子 PDF，所以先用轻量基础提取建立证据，再用 Docling 对复杂页做质量比较。
