# 第三天教学02：40题为什么推翻了10题结论

## 今天做出的东西

- 一份40题固定检索题库；
- 每题的表达、风险和知识范围标签；
- 正向题到六个候选和PDF页码的来源校验；
- 可回答命中与应拒答正确率分开的计分器；
- 错ATV产品族时不调用E5的程序拦截；
- E5前三候选的千问二次排序适配器和评测入口；
- 一份机器可读40题逐题报告。

## 最先要记住的结论

10题结果没有造假，但覆盖不够。增加口语、相似片段、错型号和无答案后：

- E5首位从90%降到76.7%；
- 混合首位从90%降到73.3%；
- E5和混合的前三仍是100%；
- 没有拒答门时，向量一定会从六个片段里挑一个，哪怕问题问价格或保修。

这说明E5 small目前更适合“先找出少量候选”，还不能单独承担“最终只选一个证据”和“判断没有答案”。

## 为什么要同时看命中和拒答

只看命中率，会漏掉最危险的一类错误：系统对不存在的知识自信返回。新的业务口径是：

```text
可回答题：正确片段是否进入前一、前三
错型号题：是否在模型调用前拒绝
当前语料无答案：是否不返回任何正式证据
```

## 关键词为什么看起来会“排名70%，业务命中43.3%”

纯关键词榜单中，21/30正确片段排第一，所以纯排名首位70%。但很多榜单第一和第二几乎打平，信心门会拒绝把这种结果交给业务，所以真正返回并答对的只有13/30，也就是43.3%。

一个指标只写“命中率”很容易误导，必须同时说明是否允许拒答、分母是什么。

## 错型号为什么不用AI判断

工单数据库已经知道设备属于ATV320。问题里写ATV930时，让E5比较相似度等于允许文字覆盖数据库事实。现在程序直接识别`ATVxxx`冲突，留下零命中记录并转人工。

可以记成：

> 数据库决定设备是谁，检索模型只决定同一设备范围内哪段资料更相关。

## 为什么不直接把前三都交给风险门

正确片段前三100%看起来很诱人，但普通复位问题的前三也可能混入“产品重启警告”“禁用错误检测危险”等高危片段。全部交给风险门会让普通问题误转人工，这正是第二天取5条曾经出现过的污染问题。

所以需要的是更准确的二次排序或独立输入风险规则，不是机械扩大数量。

## 为什么试`qwen3-rerank`

第一段E5把范围从全部知识缩到3条，第二段排序模型同时阅读问题和3条候选，判断哪条真正回答问题。阿里云官方也把排序模型定义为召回后的精准排序。

本项目先冻结30道可回答题首位至少90%的门槛，再接真实接口；没有先看结果调标准。

## 真实接入失败教会了什么

真实接口40次全部HTTP 401，错误是`invalid_api_key`。排查发现现有密钥属于Token Plan，只能给Codex等交互工具使用，不能调用业务空间后端排序服务。

这里不能做的事：

- 不能把401写成排序模型0%准确；
- 不能换几个地址反复碰；
- 不能用同一个交互密钥继续假装生产接入。

正确处理是：保留失败报告，代码改为要求独立排序服务密钥，R196继续标记未验证。

## 当前能说和不能说

能说：

- 40题和来源校验已经完成；
- E5对30道正向题前三召回100%；
- 错型号拦截5/5，且不调用向量模型；
- 二次排序代码与门槛已准备。

不能说：

- 混合检索优于E5；
- 当前无答案拒答已经解决；
- `qwen3-rerank`已经真实达标；
- 高危扩展题阻断率已达到100%；
- 40题是生产工单分布。

## 面试时一句话讲清

> 我把10道全有答案的小题扩为30道正向、5道错型号和5道无答案题，结果推翻了原90%首位基线：E5为76.7%、门控混合73.3%，但两者前三都是100%。我把错型号从语义问题改成程序范围门，做到5/5拒答且不调用E5；同时按官方两阶段检索思路实现qwen3-rerank试验，但真实调用被Token Plan与业务空间密钥隔离阻断，因此保留R196未验证，没有把401包装成模型成绩。
