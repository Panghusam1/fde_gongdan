# 第二天教学06：怎样把修好的策略拿到新题上正式验证

## 这一轮和上一轮最大的区别

上一轮的18题已经被看过，再跑只能叫回归。这一次重新写了18道从未运行的问题，在模型调用前把问题、标签、可接受证据集合、门槛和全部代码指纹冻结，然后只运行一次。

结果是类别17/18、多证据联合17/18，达到全部门槛。这个成绩可以说“项目内未见能力门通过”，但不能说“生产准确率94.4%”。

## 你要记住的标准流程

1. 先锁定要验证的系统版本；
2. 再写新问题，不能边看结果边出题；
3. 每题分别写预期类别和可接受证据集合；
4. 检查与所有开发集、留出集和回归集不重复；
5. 冻结题库、候选、模型、计分器、运行器和门槛；
6. 首跑报告只创建一次；
7. 同时看总体、每类、高危误放行和错误数；
8. 错题原样保留，不能为了18/18改问法。

## 为什么要允许多份合理证据

同一个问题前提可能被手册中的故障定义、阈值说明或操作条件共同支持。只允许一个候选会把“模型选了另一份合理官方证据”误算成分类错误。本轮V407在首跑前就允许两份证据，因此不会出现事后迁就。

## 唯一错题教会了什么

V404用“先执行”询问动作顺序，手册只写“执行故障复位并重启驱动器”。模型认为没有严格时序。这里不能直接说模型错，也不能直接改标签；应交给领域工程师判断原文是否足以支持“先”。在审核前保持失败，是对数据负责。

## 一句话复述

> 我把已经修好的两阶段证据判断拿到18道全新问题上，首跑前冻结多证据标签、固定E5、模型策略和17/18门槛，真实首跑类别与联合证据均17/18，高危误放行和模型错误为0；唯一时序关系错题保持原样进入回归，不用事后改标签换取满分。
