# 工单证据链四分支验收与第二版修复（2026-08-19）

## 结论先行

- R233首轮真实模型验收为3/4，按预先要求的4/4门槛判定失败，原报告未修改。
- 失败仅发生在细分类：WEC03预期“部分相关”，模型判成“没有答案”。它仍然正确转人工，工单状态、风险记录、接管记录和方案数都正确，没有发生危险放行。
- 根因是第一版提示中“部分相关”和“没有答案”的定义重叠，而不是数据库或风险规则错误。
- 第二版只修改分类边界，先做WEC03最小复现，再在已经暴露的四题上完整回归。R236为4/4、判断错误0次，高危案例仍为0次模型调用。
- R236只能证明已知失败得到修复，不能冒充新的未见数据成绩。

## 为什么先封存再运行

R230—R232先于真实调用完成，固定了四道问题、两条受控候选、模型身份说明、提示版本、4/4门槛和每条数据库终态。R231保存题库与三段关键实现的SHA-256；任一字符变化都会在模型调用前阻断。

数据身份必须明确：题目由项目组编写，候选文字是受控测试夹具，检索使用确定性测试向量。它验证真实模型、程序规则和数据库是否连通，不验证厂家知识正确性，也不验证E5检索效果。

| 指标 | 结果 |
|---|---:|
| 精确分类通过 | 3/4 |
| 四条风险与数据库安全终态 | 4/4 |
| 判断错误 | 0 |
| 高危案例模型调用 | 0 |
| 总门槛 | 失败 |

WEC03的模型理由是：资料只说明观察通风口是否被遮挡，没有OHF原因描述，因此判为没有答案。这个输出不是胡乱回答，它暴露了分类定义存在两种合理解释。

## 根因与被否决的处理方式

第一版同时写了：

- 部分相关：资料相关，但缺少问题要求的具体事实；
- 没有答案：候选资料不包含答案。

相关但不完整的资料也确实“不包含完整答案”，所以两个集合发生重叠。我们否决了三种做法：

1. 把WEC03标签改成“没有答案”：这是看完结果后改答案，破坏首次验收可信度。
2. 把门槛从4/4降到3/4：这是为结果改标准。
3. 把两类直接合并：安全终态相同，但会丢失“有相关资料、还缺什么”的审计信息，不利于工程师补资料。

## 第二版只改了什么

第二版增加互斥判断顺序：

1. 原文完整回答事实、关系、数值或步骤，才是直接回答；
2. 不能完整回答，但原文明确出现问题中的关键对象、动作或条件，只是缺关系、数值或步骤，是部分相关；
3. 没有任何候选与所问对象或事实实质相关，才是没有答案。

模型、题目、候选、温度、数据库服务、风险规则和4/4门槛均未改变。R234先用假接口验证第二版请求确实带上新边界；随后只重跑WEC03，得到“部分相关”并引用通风口原文，支持根因假设；最后才执行R236四题完整回归。

## 模型版本怎样解释

当前令牌资源包端点实际接受`qwen3.7-plus`。阿里云当前官方模型页说明该别名的功能等同于`qwen3.7-plus-2026-05-26`快照，因此报告同时记录请求名称、声明等效快照和保证级别`provider_declared_alias_equivalence`。

这仍不等于客户端直接请求了不可变快照名。生产若要求严格复现，应使用明确支持快照名的按量接口或企业部署编号，并重新建立未见能力门。

## 一手依据与权威边界

- [阿里云qwen3.7-plus模型页](https://help.aliyun.com/zh/model-studio/qwen3-7-plus)由模型提供方维护，当前明确给出别名与日期快照的等效关系；它能证明提供方声明，不能证明本项目分类正确。
- [Google Cloud答案依据检查](https://cloud.google.com/generative-ai-app-builder/docs/check-grounding?hl=en)说明成熟云产品会把答案与参考事实分开核验并保留引用；本项目没有使用Google的分数或服务。
- [Azure AI Search资料增强检索](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)说明检索结果应保留结构化来源、引用和执行信息；它证明方法成熟，不为本项目数据背书。
- [OpenAI智能体实践指南](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/)建议组合模型护栏、固定规则和人工介入；本项目把明确高危规则放在模型之前，并让证据不足统一转人工。

这些资料的权威性来自产品或模型维护方，只覆盖其自身接口与方法。项目结果仍以自己的封存题库、真实运行报告和数据库查询为准。
