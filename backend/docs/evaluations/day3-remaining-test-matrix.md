# 第三天剩余测试矩阵

这份矩阵区分“现在可以自动测”“需要新资料”“必须由真实业务方参与”，避免拿项目自建数据代替生产验证。

| 优先级 | 测试对象 | 需要的数据 | 核心指标 | 当前状态 |
|---|---|---|---|---|
| P0 | 来源身份新未见复验 | 新编且未运行的资料编号、版本、语言问题 | 分类、来源联合正确率；伪造来源接受数必须为0 | 已完成结构化来源约束和第四批首次真实未见：11/12，五条无匹配来源程序拒绝5/5，错误来源接收0、判断错误0，P0能力门通过；T707保留为内容分类边界 |
| P0 | 领域风险审核 | ATV320工程师对知识片段、低风险用途和停止条件的审核结果 | 审核一致率、驳回原因、修订数量 | 缺领域工程师，不得用模型代替 |
| P0 | 真实工厂查询 | 脱敏工单、真实提问、真实人工处理结果 | 安全通过率、正确转人工率、工单闭环率 | 尚无生产数据 |
| P1 | 多故障码与多型号 | 厂家正式资料和标注问题，例如OCF、OLF及其他产品系列 | 分产品/故障码召回、证据正确率、串库数 | 当前主要覆盖ATV320/OHF |
| P1 | 资料版本冲突 | 同一资料的新旧版、撤回版、多语言版 | 当前版本命中率、旧版误引用数、语言匹配率 | 数据库规则已有，模型能力未系统测 |
| P1 | 扫描件与表格 | 扫描PDF、模糊页、跨页表格、识别错误样本 | 页级提取率、逐字引用成功率、错误片段入库数 | 当前资料主要是内嵌文字PDF |

| P2 | 性能、成本与稳定性 | 不同知识规模、并发量、网络错误和限流 | P50/P95耗时、单工单模型调用数、费用、重试成功率 | 只记录了单次评测耗时，未做负载测试 |
| P2 | 人工接管运营 | 接管队列、响应时间、工程师结论和回写记录 | 接管等待时间、处理完成率、自动流程再次触发数 | 数据库有接管记录，尚无真实运营数据 |

## 推荐执行顺序

1. 来源身份能力门已通过，下一步引入第二个故障码和一组新旧版本资料，验证知识边界；
2. 正常工单和来源不匹配拒绝演示、简历与总结已经完成；
3. 后续建立扫描件识别集和系统对抗集；
4. 获得脱敏真实工单与领域工程师审核后，才报告业务效果；
5. 最后迁移到正式 PostgreSQL 环境进行并发、性能和稳定性测试。

## 不能提前宣称

- 没有真实工厂数据时，不能宣称生产工单准确率；
- 没有领域工程师审核时，不能宣称维修步骤获得专业批准；
- 没有正式PostgreSQL负载测试时，不能宣称支持生产并发；
- U301回归通过不能替代来源身份新未见测试；第四批 R320 才是本轮结构化来源架构的首次未见证据。
- 第四批是项目自建题，不能替代真实工厂数据和领域工程师审核。
