# 工单证据门主链路验证（2026-08-19）

## 验证结论

独立评测通过的“前五候选＋千问证据判断＋程序核验”已经接入工单主链路。当前实际顺序为：

```text
工单厂区、设备和产品范围
  → E5/关键词召回前五候选并留痕
  → 明确高危意图由固定规则直接阻断
  → 其他问题交给窄证据判断器
  → 程序核对候选编号、页码和引用原文
  → 只有选中的直接答案进入风险门
  → 低风险才允许后续方案；其余转人工
```

本轮新增R222—R229八项验证。R228使用外部配置中的真实`qwen3.7-plus`完成主链路调用，最终代码复跑用时约4.00秒并通过断言（首次约3.64秒）。

## 数据库终态

R228的问题为“不拆机时怎样检查通风口？”，候选同时包含低风险外部检查和高危带电作业警告。真实模型选中低风险片段后，数据库终态为：

| 记录 | 数量 | 含义 |
|---|---:|---|
| `evidence_assessments` | 1 | 保存判断、模型、提示版本、选中命中、页码和逐字引用 |
| `evidence_assessed`事件 | 1 | 工单时间线可追踪本次判断 |
| `risk_assessments` | 1 | 只检查被批准的命中，结论为`proposal_allowed` |
| `human_handoffs` | 0 | 直接证据且低风险，无需人工接管 |
| `resolution_proposals` | 0 | 本测试停在风险门，没有伪装成已经生成方案 |

## 过程中发现并修复的问题

1. 原风险门把全部检索结果视为证据。前五策略接入后，无关警告会污染正确答案，相关但答非所问的低风险片段也可能被误放行。修复为只消费证据判断选中的直接答案。
2. 协调模型原来把当前检索的全部命中编号交给方案工具。前五中包含未批准片段时，数据库正确拒绝。修复为上下文只暴露本次批准命中，并在方案工具再次核对。
3. 明确“屏蔽保护”的问题仍会先调用证据模型。R227先复现后，调整为固定高危意图规则先行，模型调用从1次变为0次。
4. 旧端到端测试没有证据判断器依赖，首次回归7项失败。补齐真实的新依赖后，又发现4项仍按“全部候选都可引用”的旧假设构造方案；修复数据边界后22项全部恢复。
5. 证据不足转人工后的相同请求先被状态门拒绝，无法读取第一次结果。R229先复现，再把顺序改为“先验权和查历史，只有新请求才检查可处理状态”，模型调用保持1次，三类记录各1条。

## 结果应该怎样解释

- R228证明真实模型、程序校验、数据库和风险门已经连通；它只有一个业务案例，不是准确率评测。
- 准确率仍引用首次运行前冻结的36题：有答案正确放行94.4%、无答案拒答100%、放行准确率100%、总体97.2%。该题库运行后已经转为回归集。
- 测试知识片段仍未获得真实ATV320工程师签字，查询也不是真实工厂日志，不能声称生产可用。
- 本轮请求使用`qwen3.7-plus`。阿里云当前官方模型页声明其功能等同于`qwen3.7-plus-2026-05-26`，但当前令牌资源包没有直接请求日期版名称，因此只能记录为“提供方声明的别名等效”，不冒充严格快照固定。后续四分支首轮与第二版修复详见[四分支验收报告](work-order-evidence-chain-holdout-v1-2026-08-19.md)。

## 一手依据及权威边界

- [阿里云百炼OpenAI兼容接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)由接口提供方维护，证明模型名、消息和结构化调用方式；不证明本项目判断一定正确。
- [Google Cloud答案依据检查](https://cloud.google.com/generative-ai-app-builder/docs/check-grounding?hl=en)把答案候选与事实分开核验，并返回支持分和引用；它证明“生成/判断后再核对来源”是成熟云产品能力。本项目没有使用Google服务，也没有照搬其分数阈值。
- [Azure AI Search资料增强检索](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)提供结构化来源、引用和执行记录，证明企业检索产品会保留来源链与运行信息；它不为本项目数据库设计背书。
- [PostgreSQL约束文档](https://www.postgresql.org/docs/current/ddl-constraints.html)说明复合外键维护跨表引用完整性；[触发器文档](https://www.postgresql.org/docs/current/trigger-definition.html)说明触发器与原语句处于同一事务，失败会一起回滚。这是选中命中、来源页、不可变审计由数据库兜底的直接依据。
- [OpenAI智能体实践指南](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/)建议组合模型护栏、固定规则和人工介入；本项目据此把高危固定规则置于证据模型之前，并把不确定结果交给人工。
