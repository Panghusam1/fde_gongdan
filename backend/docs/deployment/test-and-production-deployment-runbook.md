# 测试环境与生产环境部署运行手册

## 1. 文档目的

这份文件说明怎样把当前本地项目继续推进为可供其他系统调用的服务。它是实施方案，不是“已经部署”的证明。

当前实际状态：

- 本地 PGlite 全新数据库演示：已完成；
- 真实 E5 与千问的显式能力测试：已完成并登记；
- 网络服务入口：未实现；
- 测试 PostgreSQL + pgvector：未部署；
- 容器镜像和自动发布：未实现；
- 线上监控、备份、恢复和小流量发布：未实施。

## 2. 目标部署结构

```text
前端/企业工单系统
  ↓ HTTPS
身份认证与限流
  ↓
工单智能服务
  ├─ 请求校验
  ├─ 第四版正式主链
  ├─ 模型超时/重试/降级
  └─ 健康检查与追踪
  ↓                         ↓
PostgreSQL + pgvector       百炼生产业务空间
  ↓
备份、只读副本、监控和恢复演练

高危/证据不足 → 人工接管队列
```

## 3. 服务化前必须新增的接口

| 接口 | 作用 | 关键限制 |
|---|---|---|
| `POST /work-orders` | 确认厂区设备后创建草稿 | 必须验证用户厂区权限和设备归属 |
| `POST /work-orders/:id/messages` | 提交新的现场信息并推进一轮 | 一条请求必须有幂等编号，不能重复写入 |
| `GET /work-orders/:id` | 读取工单、方案、证据和状态 | 只允许所属厂区或接管人员读取 |
| `POST /work-orders/:id/proposals/:id/feedback` | 确认成功或反馈失败 | 只能操作当前有效方案 |
| `POST /work-orders/:id/handoff` | 人工接管 | 高危时不能被普通用户取消 |
| `GET /health` | 进程存活 | 不访问外部模型 |
| `GET /ready` | 是否可接流量 | 检查数据库迁移、模型配置、关键政策版本 |

## 4. 配置和密钥

不同环境必须使用不同配置：

| 配置 | 本地 | 测试 | 生产 |
|---|---|---|---|
| 数据库地址 | PGlite | 测试 PostgreSQL | 生产 PostgreSQL |
| 百炼密钥 | 可选个人测试 | 测试业务空间 | 独立生产业务空间 |
| 模型版本 | 固定测试版本 | 候选发布版本 | 已通过能力门版本 |
| 日志等级 | 详细 | 详细但脱敏 | 默认脱敏、错误可追踪 |
| 外部调用限额 | 很低 | 测试配额 | 成本预算与告警 |

禁止事项：

- 密钥写入 Git、镜像、测试报告或工单表；
- 测试和生产共用同一个模型业务空间密钥；
- 让协调模型获得数据库管理员凭证；
- 把完整手册、用户现场原话或内部资料无差别写入公共日志。

## 5. 数据库迁移

每次迁移必须经过：

1. 在空数据库从零执行；
2. 在上一版本备份副本上升级；
3. 检查外键、唯一约束、索引和向量维度；
4. 回放五条关键业务路径；
5. 验证旧版本应用能否在迁移期间安全停止或兼容读取；
6. 创建备份并实际恢复到另一实例；
7. 记录迁移耗时和回滚步骤。

不能只证明 `CREATE TABLE` 成功。迁移成功的业务定义是旧数据没有丢、权限没有扩大、正式主链可以继续推进已有工单。

## 6. 知识发布

知识不能上传后立即对生产可见。建议状态：

```text
已导入 → 已提取 → 已切片 → 待审核 → 已审核 → 已生成向量 → 已评测 → 已发布
                                                      ↓
                                                    已驳回
```

每次发布绑定：

- 原文件摘要；
- 资料编号、版本和语言；
- 页面和字符范围；
- 审核人、审核时间和用途分类；
- 嵌入模型与向量版本；
- 评测集和结果；
- 发布时间和撤回原因。

## 7. 容器与构建

计划要求：

- 固定 Node 主版本和依赖锁文件；
- 构建阶段运行类型检查和默认测试；
- 运行镜像不包含开发缓存、测试密钥和原始报告；
- 使用非特权用户；
- 设置只读文件系统和必要的临时目录；
- 健康检查只判断进程，避免每次探活都付费调用模型；
- 就绪检查验证数据库迁移和关键配置；
- 镜像使用不可变版本号，不使用无法追踪的 `latest` 作为发布证据。

## 8. 联调环境冒烟测试

部署到测试环境后，至少运行：

1. 创建草稿工单；
2. 无权限厂区访问被拒绝；
3. 正确来源正常形成一版方案；
4. 来源版本不匹配不调用内容模型并转人工；
5. 高危请求零方案并转人工；
6. 第一版失败后生成第二版；
7. 第二版失败后不能生成第三版；
8. 模型超时后不重复产生业务写入；
9. 重复请求编号不会创建重复工单或重复观察；
10. 从追踪和数据库审计中还原上述每一步。

## 9. 发布能力门

| 类别 | 硬门 |
|---|---|
| 代码 | 默认全量测试失败数为 0 |
| 数据库 | 空库迁移、升级迁移、备份恢复全部通过 |
| 来源 | 错误来源接收数为 0 |
| 安全 | 高危漏拦数为 0，危险误方案数为 0 |
| 工作流 | 第三版方案数为 0，人工接管可用 |
| 模型 | 新首次未见达到预冻结门槛，非法结构有程序兜底 |
| 权限 | 跨厂区和越权访问数为 0 |
| 运维 | 健康、就绪、日志、指标、告警和回滚均已演练 |

## 10. 小流量发布

生产发布不直接全量开放：

1. 先让真实请求只记录、不影响现有流程；
2. 与工程师结果对比，形成脱敏评测数据；
3. 只向内部测试人员提供建议，不自动执行；
4. 从低风险、资料充分的范围开始；
5. 逐步扩大流量，每一步都重新检查硬门；
6. 高危、证据不足和异常调用始终转人工。

## 11. 监控和告警

最低监控项：

- 接口成功率、P95 耗时、超时与重试；
- 数据库连接、慢查询、锁等待、磁盘和备份；
- 向量检索耗时、候选数、空结果率；
- 模型调用次数、耗时、令牌量、限流和费用；
- 来源不匹配率、证据不足率、高危率、转人工率；
- 第一版和第二版结果、第三版阻断数；
- 人工队列积压和等待时间；
- 错误来源接受、高危漏拦、危险误方案三个零容忍指标。

## 12. 回滚表

| 变化 | 回滚方式 | 回滚后验证 |
|---|---|---|
| 应用代码 | 切回上一不可变镜像 | 双分支冒烟和权限测试 |
| 数据库结构 | 执行已演练回滚或从备份恢复 | 数据条数、外键、已有工单 |
| 知识版本 | 撤回新版本并恢复上一发布版本 | 来源过滤和引用 |
| 向量版本 | 恢复上一嵌入版本的索引 | 固定检索回归集 |
| 模型/提示 | 切回上一模型与提示版本 | 协调轨迹和证据判断回归 |
| 安全政策 | 恢复上一已审核政策 | 高危与正常误阻断集 |

## 13. 当前项目下一步实施顺序

1. 把主链封装成内部 HTTP 服务；
2. 用正式 PostgreSQL + pgvector 替换服务运行时 PGlite；
3. 增加鉴权、幂等请求和事务边界；
4. 增加健康、就绪、结构化日志和请求追踪；
5. 编写容器和本地测试环境编排；
6. 跑迁移、并发、超时、重试和安全冒烟；
7. 获得脱敏工单和领域工程师审核；
8. 再讨论生产小流量发布。
