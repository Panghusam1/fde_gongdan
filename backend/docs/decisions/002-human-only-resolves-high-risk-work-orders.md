# 设计决定 002：高危工单只能由人工工程师确认解决

- 决定日期：2026-08-17
- 决定人：项目学习者
- 状态：已确认

## 业务决定

工单一旦触发高危阻断，只有具备相应权限的人工工程师可以把它从“人工处理中”改为“已解决”。AI可以整理工程师提交的处理记录，但不能代替工程师确认问题已经解决。

## 允许的流程

```text
排查中
→ 等待人工
→ 人工处理中
→ 已解决
→ 已关闭
```

## 禁止的流程

```text
等待人工 → AI直接标记已解决
人工处理中 → AI直接标记已解决
等待人工 → 直接关闭
人工处理中 → 直接关闭
```

## 对数据库和程序的影响

- 需要用户表和角色/权限记录，不能只保存审批人姓名。
- 需要工单状态变化记录，保存操作者、原状态、新状态和时间。
- 需要保存高危判断以及触发的规则，不能只保存一个最终状态。
- 状态转换入口必须验证操作者角色。
- 高危工单进入“已解决”前，必须存在完整的人工处理记录。
- AI生成的整理内容必须与人工确认记录分开保存。

## 后续必须编写的反向测试

- AI尝试把高危工单改为“已解决”时必须失败。
- 普通用户尝试把高危工单改为“已解决”时必须失败。
- 没有人工处理记录时，高危工单进入“已解决”必须失败。
- 高危工单从“等待人工”直接进入“已关闭”必须失败。
