# 设计决定 008：官方资料与版本管理

- 日期：2026-08-18
- 状态：已通过测试实现
- 适用范围：第一周项目的官方资料目录和资料版本

## 要解决的问题

系统不能只保存一个 PDF 路径。它必须分清：

1. 这是一份什么资料；
2. 这份资料有哪些语言和版本；
3. 哪一版经过核验、当前允许使用；
4. 某个文件是否已经导入过；
5. 资料适用于哪个规范产品系列。

## 考虑过的方案

### 方案一：一份资料只保留一个文件路径

优点是表少、导入快。缺点是新版会覆盖旧版，已经生成的工单无法还原当时使用的资料，不适合维修建议审计。

### 方案二：每个 PDF 都是一份独立资料

优点是不用处理版本关系。缺点是同一手册的不同语言、不同版本会互相分散，系统无法可靠回答“当前应该用哪一版”。

### 方案三：逻辑资料与不可覆盖的资料版本分开

一行逻辑资料表示“这是什么”，多行版本表示“它在什么时间、什么语言下有哪些文件”。版本只追加，不覆盖。新导入版本默认待审核，同一语言只能有一个当前有效版。

选择方案三。

## 数据库负责保证什么

- 资料必须连接真实存在的规范产品系列；
- 旧资料只连接已有且名称吻合的规范系列，不自动猜造主数据；
- 资料类别只能使用已经设计的四种允许值；
- 新版本默认待审核；
- 版本状态只能是待审核、当前有效、已被取代、已撤回；
- 同一资料同一语言只能有一个当前有效版；
- 同一资料、版本、语言和文件指纹不能重复导入；
- 同一发布机构与文件编号不能靠大小写或空格重复建档。
- 正式种子导入必须核对已有逻辑资料的产品系列和资料类别；冲突时在事务中失败。

## 数据库不能独自保证什么

- 下载页面是否真属于厂商；
- PDF 是否被发布方错误标注；
- 抽取文字是否忠于原文；
- 某一版是否适用于现场固件、选件和接线条件；
- 发布方是否已经发布了数据库尚未发现的新版本。

这些问题必须由导入程序、定期检查和人工审核共同保证。AI可以整理差异并提出“建议设为当前版”，不能自己批准自己。

## 行业与标准依据

- 真实案例资料来自[施耐德电气 ATV320 中文编程手册 NVE41300](https://www.schneider-electric.cn/zh/download/document/NVE41300/)。官方页面明确给出文件编号、中文、版本 05、日期 2025-07-04 和适用产品 ATV320。
- ServiceNow 的知识管理业务会保留文章的多个版本，区分审核、已发布、过时和退役等状态，并支持把某一历史版本设为当前版；我们借鉴“保留历史 + 明确当前版”，但没有照搬它完整的内容发布流程。[ServiceNow 文章版本管理](https://www.servicenow.com/docs/r/servicenow-platform/knowledge-management/article-versioning.html)
- SharePoint 的文件版本历史支持恢复旧版本，而且恢复时不会抹掉历史；我们借鉴“版本不覆盖”，但本项目额外加入了工业资料的待审核和撤回状态。[Microsoft SharePoint 版本历史](https://support.microsoft.com/en-us/sharepoint/documents-and-library/restore-a-previous-version-of-an-item-or-file-in-sharepoint)
- PostgreSQL 官方文档说明：只对部分记录生效的唯一性，应使用唯一部分索引。本项目据此只对 `version_status = 'current'` 的记录限制“同一资料同一语言只能有一个”。[PostgreSQL 约束文档](https://www.postgresql.org/docs/current/ddl-constraints.html)
