# 决策024：证据判断改为两阶段固定流程，并把分类与证据标签分开计分

## 状态

已完成项目内已见回归和审定分析；原R255联合门槛仍记失败。尚未经过新的未见题库和领域工程师验收，不得作为生产策略批准。

## 触发问题

第二版提示在四条旧题上回归4/4，但换成18道首次未见题后只有11/18，其中“部分相关”0/6。第三版用完整互斥提示后提高到15/18，却仍同时出现两种相反错误：相关资料被判完全无答案，以及不同业务单元因表面词相同被判部分相关。

继续追加提示会针对已暴露题过拟合。更重要的是，单次调用同时要求模型判断业务对象、判断答案完整性、选择最终类别、选择资料并逐字引用，职责过多，任何一项失败都会让整题失败。

## 备选方案

| 方案 | 优点 | 缺点 | 决定 |
|---|---|---|---|
| 继续增加分类例子 | 改动小、调用一次 | 已连续出现规则选择性失效，容易过拟合 | 否决 |
| 直接把部分相关和无答案合并 | 安全动作更简单 | 丢失知识缺口类型，无法指导补资料 | 否决 |
| 多智能体讨论后投票 | 可引入多视角 | 成本、时延和不可控性高，当前任务边界固定 | 否决 |
| 两阶段固定流程 | 每步单一、程序可审计、错误可定位 | 相关题由一次调用增为两次 | 采用 |

## 决策

当前候选策略使用固定流程，而不是让模型自由编排：

```text
E5前五候选
  → 第一次模型调用：只判断同一业务对象、前提有依据、最终事实有依据
  → 程序按三个布尔值生成最终类别
  → 完全不可回答：直接停止
  → 直接回答或部分相关：第二次模型调用只选候选、页码和连续原文
  → 程序校验候选存在、页码存在、引用属于连续原文
```

它仍是一个协调流程，不是多个自治智能体。模型负责难以用固定规则完成的语义核对，程序负责类别映射、字段校验和停止条件。

## 评测结果怎样解释

- R243首次未见首跑：11/18，失败；
- R247单次完整提示回归：15/18，失败；
- R255两阶段回归：原始“类别＋唯一候选”16/18，失败；
- R255单看类别：17/18；
- 使用完整回归前已经封存的V307多证据歧义做审定分析：17/18；
- 所有轮次高危误放行均为0；第五版模型错误和引用错误均为0。

原冻结R255不能改成通过。审定分析只证明原指标把“类别错”和“另选一份同样合理的证据”混在了一起。

## 标签规则调整

后续题库必须分别保存：

- `expected_verdict`：预期类别；
- `acceptable_candidate_ids`：允许一份或多份合理证据；
- 标签理由和官方页码；
- 标注人、复核人和审核状态。

当前V307审定仍是项目组临时结论，尚无ATV320工程师签字。

## 成熟实践依据

- [Anthropic的智能体工程方法](https://www.anthropic.com/engineering/building-effective-agents)区分固定代码路径的工作流和模型自主决定流程的智能体，并明确复杂度通常用时延和成本换效果；这支持本项目选择可预测的两阶段工作流，而不是增加自治智能体。
- [阿里云百炼结构化输出文档](https://help.aliyun.com/en/model-studio/qwen-structured-output)说明`json_object`的使用方式，并明确建议在程序侧继续做字段与格式校验；这对应本项目“模型给JSON，程序仍验证布尔值、候选、页码和逐字引用”。
- [微软研究院关于评分不确定性的研究](https://www.microsoft.com/en-us/research/publication/validating-llm-as-a-judge-systems-under-rating-indeterminacy/)指出强迫只有一个正确标签会在存在多种合理解释时扭曲评测，并研究多标签答案集合；这直接支持后续使用可接受证据集合。
- [OpenAI模型迁移与评测指南](https://developers.openai.com/api/docs/guides/latest-model)建议一次只改一个变量并在每个小变化后重跑评测；本项目用封存候选顺序隔离了提示或编排变化。

这些资料证明方法和产品能力成熟，不证明本项目的工业标签正确。工业正确性仍需要施耐德官方手册来源链和设备工程师审核。
