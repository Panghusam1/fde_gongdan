# 设计决定 001：确认厂区和设备后创建草稿工单

- 决定日期：2026-08-17
- 决定人：项目学习者
- 状态：已确认

## 业务决定

用户成功确认有权访问的厂区和具体设备后，系统立即创建一张草稿工单。后续现场描述、资料检索、引用证据、风险判断、状态变化和人工转交都持续记录在这张工单下。

## 为什么这样设计

- 问题没有解决时也能保留处理过程。
- 高危阻断发生前后的上下文不会丢失。
- 人工工程师接手时可以看到AI已经询问和检索过什么。
- 最终工单是全过程记录，不是结束后生成的一段摘要。

## 创建草稿前必须满足

- 当前用户已经通过身份验证。
- 用户有权访问所选厂区。
- 厂区真实存在。
- 设备真实存在。
- 设备确实属于所选厂区。

## 创建草稿时暂时不要求

- 不要求已经确定故障原因。
- 不要求已经找到官方资料。
- 不要求已经形成处理结论。
- 不要求已经完成人工审批。

## 对数据库设计的影响

- 工单必须保存厂区和设备关联。
- 工单初始状态固定为 `draft`，界面显示“草稿”。
- 后续需要建立工单事件表，保存草稿创建后的每一步。
- 工单创建和第一条“创建草稿”事件需要放在同一事务中。
