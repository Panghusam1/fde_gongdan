# 设计决定019：用固定工单过程评测真实协调模型

## 要解决的问题

两次真实模型冒烟调用只能证明接口可用和单个动作格式正确，不能证明协调模型能在工单不同阶段持续选对动作。第三天因此增加一套可版本化、可重复执行的真实模型评测。

## 比较过的方式

| 方式 | 优点 | 当前缺点 | 结论 |
|---|---|---|---|
| 只看最终回答 | 便宜、容易演示 | 看不到跳步骤、错编号和越权动作 | 拒绝作为Agent验收 |
| 只做两个单轮冒烟测试 | 能确认接口接通 | 样本和流程覆盖不足 | 保留为接入检查 |
| 固定数据库上下文，逐轮检查动作和参数 | 结果可重放，能定位具体错误 | 没有真正执行工具和改变数据库 | 采用为决策层基线 |
| 真实模型驱动真实工具和数据库到终态 | 最接近产品 | 搭建和运行成本更高，失败定位更复杂 | 作为下一层验收，不与本基线混称 |

## 为什么评测的是过程，不只看结尾

工单最后显示“已解决”，并不能证明中间没有跳过风险判断、引用错误证据或让模型自行宣布恢复。当前题库因此保存每一轮的数据库式上下文、允许动作、预期动作和参数约束，并保留真实模型输出。

[Anthropic的Agent评测工程文章](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)把过程记录定义为一次试验中包含模型输出、工具调用、中间结果等内容的完整记录，并强调失败后要阅读记录，区分模型错误和评分器误判。它是评测方法的一手工程经验，不是本项目准确率的证明。

## 数据与门槛为什么先冻结

第一版包含20个案例、40轮调用，覆盖正常处理、现场信息记录、第一版失败后第二版、两版失败转人工、高危、证据不足、提示注入和型号范围冲突。所有案例都是根据本项目业务规则编写的模拟工单，不冒充真实厂区分布。

联网前固定四个门槛：

- 合法结构输出率100%；
- 动作正确率至少90%；
- 参数正确率至少85%；
- 整条过程通过率至少80%。

先冻结是为了防止看到成绩后降低标准。原始数据通过SHA-256绑定，v1结果不回写覆盖；需要修正规则时新增v2。

## 四个指标分别回答什么

- 合法结构输出率：程序能否解析并接受输出，不代表业务正确；
- 动作正确率：模型是否选中该轮预期工具；
- 参数正确率：动作正确后，编号、非空字段和禁止词是否满足要求；
- 整条过程通过率：一个案例的所有轮次是否全部正确，能反映错误传播风险。

## 第一次真实结果和新发现

真实`qwen3.7-plus`、`coordinator-v2`在20个案例、40轮上得到：结构100%、动作92.5%、参数92.5%、整条过程85%，达到预先门槛。

三个未完整通过的案例都发生在第一轮。题库要求立即检索，模型却选择了同样处于许可表中的“记录现场信息”。模型没有执行拆机、跳过确认或宣布解决，所以不能把这三次简单归类为安全失守；它们暴露的是动作许可和单一标准答案之间的歧义。

进一步检查协调循环发现：同一用户消息会在一次运行的多个步骤中重复传入。如果模型先选择记录，而许可表仍同时允许记录和检索，存在重复记录直至达到步数上限的风险。这是编排层问题，不能只靠提示词修饰。

## 当前处理决定

1. 保留v1原始结果和三个失败，不回改答案；
2. 不降低门槛，也不把85%写成100%；
3. 已由R188先复现“达到最大步数”，再实现运行内输入消费规则：记录一次后，程序从本轮后续有效许可中移除追加动作；
4. v2应区分“多个业务上可接受的动作”和“只有一个正确动作”，并增加真实工具、真实数据库状态变化的端到端试验；
5. 高危仍由程序风险门和人工接管决定，模型动作选择不能解除阻断；R188只验证单次消费，不替代高危端到端验收。

## 一手资料依据和适用边界

- [OpenAI Agent构建实践](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/)：建议先建立评测基线、定义清楚动作，并把高危和超过失败次数作为人工介入条件。它支撑“先评测、清动作、留人工门”，不证明本项目已经生产可用。
- [Anthropic Agent评测工程文章](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)：支撑保存完整过程、检查失败记录和防止评分器误判。
- [阿里云百炼错误码与结构化输出说明](https://help.aliyun.com/zh/model-studio/error-code)：支撑JSON模式、提示中包含JSON以及关闭不兼容思考模式的接口设置。它只保证接口要求，不保证动作语义正确。
