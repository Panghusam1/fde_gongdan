# 设计决定022：0.86无答案阈值盲测失败，不接入主链路

## 为什么要单独做留出测试

40题开发集中，5道无答案题的E5最高分都低于0.86，而可回答题首位最低约为0.860。直接在同一批题上设0.86再宣布成功，属于用答案调考试题。

因此先冻结一套24题留出集和三项门槛，再第一次运行模型：

- 12道可回答题，每个候选2题；
- 12道当前六片语料无答案题；
- 与40题开发集没有重复；
- 候选阈值固定0.86；
- 可回答正确接收至少75%；
- 无答案正确拒答100%；
- 被接收结果的准确率至少90%。

题库首次运行前SHA-256为`0d3b8db4a65c00da728afaaaee8270ac3e2ffb23df68993b8ad89745eb4f6894`，冻结记录保存在`reports/ohf-answerability-holdout-v1-prerun.json`。

## 第一次且不回改的结果

| 指标 | 结果 | 门槛 | 是否通过 |
|---|---:|---:|---:|
| 可回答正确接收 | 91.7%（11/12） | ≥75% | 是 |
| 无答案正确拒答 | 83.3%（10/12） | 100% | 否 |
| 被接收结果准确率 | 84.6%（11/13） | ≥90% | 否 |
| 总体决策正确率 | 87.5%（21/24） | 未设门槛 | 观察项 |

三道失败：

- H11是真实可回答的断电隔离问题，但最高分0.8588且第一名排错，形成错误拒答；
- H14问保修售后，却以0.8686错误匹配热阈值；
- H19问风扇备件编号，却以0.8653错误匹配OHF定义。

## 为什么不继续挪阈值

把阈值提高到0.869附近虽然可能挡住H14、H19，却是看完留出答案后调参；而且H11不仅分数低，第一名本身也错了，单一阈值无法修复排序。

[Elastic官方kNN文档](https://www.elastic.co/docs/solutions/search/vector/knn)明确说明最近邻总会努力返回若干结果，并提供最低相似度过滤。它证明阈值是成熟产品能力，但没有承诺一个阈值能跨语料判断“是否存在答案”。本次盲测正好证明阈值必须由本业务数据验证。

[Anthropic Agent评测方法](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)建议用平衡题集同时测试行为应发生和不应发生的场景，保留过程与结果，并把能力评测和回归评测分开。其权威性来自模型与Agent产品团队的公开工程实践；它不替代本项目领域验收。

## 当前决定

1. 不把0.86接入正式检索，也不改写失败题库；
2. 现有向量结果继续叫“候选召回”，不能叫“答案存在证明”；
3. 风险门仍要求检索证据同时具备`low_risk_guidance`用途，否则以证据不足转人工；因此错误召回不会自动变成现场方案；
4. 下一候选是“检索后判断证据是否直接回答问题”，但必须先冻结新题和门槛，再验证模型或规则，不能在本留出集上继续追分；
5. 收集真实工单问题后，按产品主题、可回答/无答案和误报成本重新校准。

## 这一失败为什么值得写进简历

它证明项目不是“调到一个好看的阈值”，而是建立了防止自我欺骗的过程：开发集提出假设、留出集冻结摘要、第一次运行失败、逐题定位、拒绝上线不达标策略。
