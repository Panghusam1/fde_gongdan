# 设计决定 004：增加“等待用户确认”状态

- 决定日期：2026-08-17
- 决定人：项目学习者
- 状态：已确认

## 业务决定

AI生成满足要求的低风险处理方案后，工单从“排查中”进入“等待用户确认”。该状态表示系统已经提供方案，正在等待现场用户完成允许范围内的处理并反馈实际设备状态。

## 进入该状态的必要条件

- 厂区、设备、产品系列和具体型号已经确认。
- 已保存一份明确版本的处理方案。
- 处理方案引用了可追溯的官方资料证据。
- 处理方案没有包含需要转人工的高危操作。
- 已保存本次风险判断结果。

缺少任何一项，都不能进入“等待用户确认”。

## 允许的后续变化

```text
等待用户确认
├─ 用户确认设备恢复正常 → 已解决
├─ 用户反馈没有恢复 → 排查中
├─ 用户补充的信息触发高危规则 → 等待人工
└─ 用户取消本次处理 → 已取消或继续保留，需后续单独决定
```

## 禁止的变化

```text
等待用户确认 → AI直接标记已解决
等待用户确认 → 没有用户反馈直接标记已关闭
等待用户确认 → 没有人工处理记录却解决高危工单
```

## 对数据设计的影响

- 需要处理方案表，并保留方案版本。
- 需要用户确认记录，保存实际执行结果。
- 需要工单状态变化记录。
- 需要记录进入“等待用户确认”的时间，支持超时提醒。

## 后续必须编写的反向测试

- 没有处理方案时进入“等待用户确认”必须失败。
- 方案没有引用证据时进入“等待用户确认”必须失败。
- 方案包含高危操作时进入“等待用户确认”必须失败。
- 没有用户确认记录时进入“已解决”必须失败。
