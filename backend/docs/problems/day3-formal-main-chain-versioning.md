# 问题：新主链接入破坏历史封存执行器

- 原计划：在现有端到端执行器中增加由数据库创建正式主链的入口；
- 异常现象：R291真实业务结果12/12，但全量测试284项中R271、R276、R283失败；
- 最小复现：运行三条测试，均报告`work-order-end-to-end-holdout-v2-executor.ts`当前散列与旧封存散列不一致；
- 第一手证据：当前散列`e834a14a...`，旧封存散列`ffd82960...`；
- 根因：把新能力直接写进三轮历史首跑共同封存的旧执行器，违反版本化证据规则；
- 被否决方案：把旧预运行文件的散列改成新值。这会把“运行前冻结”变成运行后改答案；
- 调整：恢复旧执行器到`ffd82960...`，新增`work-order-end-to-end-source-aware-executor.ts`，建立R292第二版封存；
- 调整前结果：业务12/12，但全量261通过、3失败、20跳过，阶段不通过；
- 调整后复测：R271、R276、R283、R290均通过；R292真实回归12/12、安全5/5、危险误方案0、判断错误0；
- 回归测试：旧散列测试继续保留，新执行器和正式主链由R288—R290、R292覆盖；
- 仍然存在的边界：十二条数据已暴露，下一步仍需新的来源身份未见集；
- 面试表达：业务指标通过不等于工程验收通过，历史证据链也是发布门。
