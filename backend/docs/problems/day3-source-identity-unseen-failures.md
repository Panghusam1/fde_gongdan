# 来源身份未见测评为什么连续推翻提示词方案

## 现象

- 第六版：`S409` 要求忽略第05版并当作第06版，模型错误放行；
- 第七版：已知覆盖问题修复，但第二批出现语义误拒绝和多候选波动；
- 第八版：已知语义与多候选问题修复，但 `C606` 要求把 `zh-CN` 视作 `en-US` 时再次错误放行。

## 排查证据

`S409` 单独复跑仍放行，证明不是一次随机输出。`P502` 单独复跑仍拒绝，证明“范围”语义缺口稳定存在。`P511` 第二次从拒绝变为正确选择，证明多候选共同判断存在波动。

## 被否决的调整

1. **继续补覆盖指令样例**：新表达可以继续绕过，不能穷举；
2. **把温度设为0就认为确定**：真实复跑已经证明同一多候选问题仍会变化；
3. **只看总正确率**：第三批 `11/12` 看似达标，但错误放行触发安全硬门；
4. **修改失败题标签或覆盖首次报告**：会破坏未见测评的可信度；
5. **只用正则从自由文本猜最终版本**：比较旧版与当前版的正常问题也可能同时出现多个版本号，无法可靠判断哪个是用户确认的目标。

## 根因

系统把两类职责混在了同一次模型判断中：

- 结构化来源约束：资料编号、版本、语言；
- 非结构化内容判断：正文能否回答问题。

前一类需要确定性一致性，后一类才适合模型做语义判断。让模型同时完成两类任务，提示词再强也会受到自然语言覆盖方式和候选顺序影响。

## 后续调整与结果

已新增用户确认后的 `requestedSourceIdentity`、原始问题和确认内容三类字段。数据库先按编号、版本、语言过滤；无匹配时程序直接拒绝且不调用模型，有匹配时只把匹配候选交给内容判断器。

第四批首次真实未见得到 11/12：五条无匹配来源全部在程序层拒绝，错误来源接收 0、判断错误 0。唯一差异是 T707 的“部分相关/不能回答”内容分类边界，未再出现来源覆盖。三轮失败因此没有被删除，而是成为架构调整的因果证据。
