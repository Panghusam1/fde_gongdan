# 阶段八面试题：确定性风险门、现场观察和人工接管

## 30秒介绍

我在工业知识检索与方案生成之间实现了不可绕过的风险门。程序根据已审核证据的危险等级、系统用途和内容种类执行版本化规则；协调模型只能提高风险，不能降低程序结论。低风险且证据充分才允许进入方案生成，高危或证据不足会在同一事务中保存判断、规则命中、人工接管、工单事件和等待人工状态。现场观察只追加，为后续第二版方案是否具有新信息提供可审计依据。

## 核心架构

```text
现场观察 → 工单事件
                 ↓
检索运行 → 固定规则判断 ─┐
                         ├→ 取较高风险 → 允许方案 / 人工接管
模型语义风险建议 ────────┘
```

## 高频问题

### 1. 为什么不让千问直接判断风险？

固定高危条件不能依赖概率输出。模型适合发现规则未覆盖的可疑表达，因此只获得升级权，没有降级权。

### 2. 为什么检索到危险警告就不直接删除结果？

危险警告仍是重要证据，可以解释为什么系统停止自动指导。系统禁止它进入低风险步骤，但保留引用和审计。

### 3. 为什么没有证据也创建风险判断？

“当前资料不足”本身决定流程必须停止。保存零结果判断才能证明系统没有凭常识生成方案，也方便统计知识缺口。

### 4. 为什么风险规则放数据库？

规则需要代码、版本、启用状态和历史命中。只写在提示词里无法稳定执行，也无法还原历史判断采用了哪版规则。

### 5. 为什么判断表和命中表分开？

一次判断可能命中多条规则和多条证据。主表保存最终结果，命中表保存一对多解释，避免把证据编号塞进一格数组逃避关系约束。

### 6. 如何防止跨工单拼接证据？

风险判断通过复合外键绑定工单、厂区、设备和检索运行；命中表再把判断与检索命中绑定到同一个检索运行。

### 7. 为什么现场观察不能修改？

两版方案限制依赖“第一版失败后是否出现新信息”。覆盖旧观察会破坏判断依据，所以只能追加更正或新观察。

### 8. 当前还有什么没完成？

带证据方案、现场确认、第二版限制、两版失败转人工、千问协调循环和40题总验收尚未完成。

## 问题与调整台账

### 测试夹具没有规范型号

- 现象：观察工具测试在加载工具之前就失败；
- 证据：数据库报告`equipment_model_id`违反非空约束；
- 根因：测试设备不符合已经确定的业务模型；
- 调整：补充测试产品族和规范型号，不修改生产约束；
- 结果：测试随后因目标工具不存在而正确变红。

### 等待人工状态没有接管记录

- 原实现：风险阻断后只修改工单状态；
- 问题：无法分派、接单、统计原因，也不能证明真的发起了转交；
- 调整：新增`human_handoffs`和R150—R151；
- 结果：高危与证据不足分别生成接管原因，和状态、事件一起提交。

### 多条命中逐条写入

- 问题：一次判断最多可能命中多条规则，逐条插入增加往返；
- 调整：在保持短事务的前提下改为批量插入；
- 边界：当前PGlite验证不能代替生产PostgreSQL并发压测。
