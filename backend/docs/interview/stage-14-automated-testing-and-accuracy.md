# 阶段十四面试题：自动化测试与准确率提升体系

## 30秒介绍

我把项目测试拆成数据库约束、纯函数、窄工具、完整业务链、真实模型能力门和真实业务验收六层。默认回归只跑稳定无费用的部分；所有默认跳过的模型测试由R204强制登记原因、运行命令、最近真实状态和报告证据。准确率方面，我把开发集、留出集和回归集分开，分别统计召回、细排、拒答、协调动作和业务终态，禁止在同一留出集调参后宣布成功。

## 高频问题

### 1. 为什么模型测试默认跳过？

为了让日常回归不依赖付费接口、网络和本地模型缓存。但跳过项必须有显式命令和真实状态；目前四项通过、一项受权限阻断、一项真实效果失败。

### 2. 自动化测试怎么设计？

先把业务风险写成不可违反的规则，再准备输入、正确结果和来源，先看测试失败，然后实现最小改动，最后跑局部和全量回归。模型能力另外用固定题库、评分器和预冻结门槛评测。

### 3. 为什么不能只看总体准确率？

总体数字会把无答案乱答、高危漏拦和正常问题误转人工混在一起。工业场景必须分别看首位/前三、无答案拒答、高危召回、误阻断、接收准确率和最终工单状态。

### 4. 当前怎样提高检索准确率？

E5前三在40题开发集已经100%，所以没有先换嵌入模型。0.86无答案阈值失败后，改为E5前五加独立证据判断：旧24题回归100%，新36题首次运行得到94.4%有答案正确放行、100%无答案拒答和100%放行准确率。二次排序R196仍缺后端密钥，新策略下一步接入工单主链路。

### 5. 如何防止为了指标过拟合？

开发集用于调整；留出集在运行前冻结题目、摘要、模型、规则和门槛；看过留出结果后不能继续调并在同集验收。失败案例进入回归集，新方案必须使用新的留出集。

### 6. 测试通过是否等于可以上线？

不等于。当前还缺真实领域审核、真实工厂查询、服务端PostgreSQL并发验证、合法排序服务密钥和依赖风险处置。项目测试只能说明已经覆盖的规则和数据范围。
