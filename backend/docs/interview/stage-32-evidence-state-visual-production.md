# 阶段三十二：证据状态配图生产与真实性边界

## 30秒介绍

工单证据状态已经结构化以后，我为高危阻断、证据不足、资料版本冲突、厂区权限阻断和尚未检索五类状态分别生产了独立工业配图，并建立六状态到六资源的一对一映射。配图提升现场演示辨识度，但不参与业务判断：页面把手册关系图标为“来源示意”，其他生成图标为“状态示意”，证据结论仍由后端状态、资料身份、页码和原文决定。

## 核心决策

### 为什么不继续复用同一张图

同图会让不同业务状态视觉上无法区分，也容易再次造成“高危或越权工单已经取得手册证据”的误解。

### 为什么不在图片里生成结论文字

生成图片中的小字不可靠，而且会形成图片文案和后端状态两套事实源。因此图片只负责表达场景，状态名、核验问题和原因仍由 React 读取后端数据展示。

### 为什么必须标注“状态示意”

生成图不是客户现场照片，也不是官方手册原页。若不标注，视觉真实性可能被误认为数据真实性。清楚标注可以保留演示效果，同时守住简历和面试中的事实边界。

## 测试策略

- 测试先固定六个唯一资源路径和文件存在性；
- 组件通过 `evidenceStateImages[evidencePreview.state]` 选择图片；
- 浏览器依次切换高危、版本冲突、证据不足、权限阻断和待检索工单，检查图片路径、加载状态和替代文字；
- 任意图片删除、路径写错或映射丢失都会使前端测试失败。

## 问题与调整台账

| 问题 | 风险 | 调整 | 验证 |
|---|---|---|---|
| 非手册状态只有纯文字卡 | 演示辨识度不足 | 为五类状态各生成独立工业图 | 浏览器逐项切换并检查资源路径 |
| 生成图可能被误认成真实证据 | 夸大数据真实性 | 图片角标区分“来源示意”和“状态示意” | 组件测试固定边界文案 |
| 图片内生成业务文字 | 文字错误且形成双事实源 | 图片禁止可读文字，结论由后端字段渲染 | 目视检查与 DOM 检查 |

## 简历与面试可用表述

> 为六类工单证据状态建立一对一视觉映射，使用无业务文字的工业场景配图提升现场演示辨识度；将生成图明确标为状态示意，业务结论继续由后端结构化证据状态和来源字段驱动，并以资源存在性测试和真实浏览器逐项切换防止图片串单。

## 不能夸大的范围

- 五张新增图片是生成的状态示意，不是现场照片；
- 图片不参与检索、证据判断或风险判断；
- 手册关系图也不是官方 PDF 页面截图，官方原文仍以资料编号、页码和逐字摘录为准。
