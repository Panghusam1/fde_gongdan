# 阶段二十七：可运行演示与项目最终交付

## 30秒回答

项目最终交付不是一份文档，而是一条可重复运行的命令。`npm run demo` 会用两套全新数据库分别演示正常闭环和来源不匹配：正常路径产生一版证据方案并确认解决；来源不匹配路径不调用内容模型、不生成方案，保存证据不足并转人工。演示复用真实迁移、官方页面摘录和业务工具，外部模型替换为可控实现，真实模型能力则由独立冻结报告证明。

## 为什么演示和模型评测要分开？

演示要求稳定、快速、能讲清数据库终态；模型评测要求真实模型、预先封存和保留波动。用真实模型做演示可能因网络和随机性失败，用可控模型成绩冒充准确率又不诚实，因此两者必须分开。

## 演示覆盖了什么？

- 真实数据库迁移与官方资料种子；
- 已审核知识的索引与工单范围检索；
- 第四版结构化来源过滤；
- 证据判断、固定风险门、方案、现场反馈和人工接管；
- 两条路径的数据库计数和最终状态。

## 遇到的问题

旧端到端执行器要求一个固定判断器，而第四版来源判断器必须在知道本次检索问题和确认来源后绑定。最终没有修改已封存执行器，而是在其公开的主链工厂入口中创建第四版主链，再为单条演示工单绑定确认请求。这样既复用了真实数据库流程，也保持历史首跑散列不变。

## 简历可写

将工业智能工单项目封装为无需外部服务的可重复演示，以两套全新数据库验证正常解决与来源不匹配人工接管路径；正常路径形成完整证据、风险、方案和反馈记录，来源不匹配路径保持零内容模型调用、零方案和一条接管记录。
