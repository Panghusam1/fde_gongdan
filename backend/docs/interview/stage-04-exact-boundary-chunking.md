# 阶段四面试题：结构切片与页内精确证据

- 项目：ATV320 变频器智能工单系统
- 阶段日期：2026-08-18
- 阶段范围：切片方案比较、页内精确范围、候选创建服务、真实OHF候选包
- 本阶段规则：R92—R112
- 当前产物：6组真实候选、8条精确来源，全部待审核
- 当前验证：全项目105项自动化测试通过，0失败

## 一、30秒介绍

我没有把440页手册按固定字数直接切开，而是先用OHF真实页面比较固定长度、一页一段、模型语义切分和结构切分。最终采用结构规则为主、长度为辅：一个故障项、参数项或完整警告块作为业务边界。数据库记录片段在具体页面提取正文中的起止字符和逐字摘录，并反查原页验证。协调助手只能提出摘录，创建服务自己定位、拼接机器原文并写成待审核候选，不能自动批准。最后从真实手册第50、72、310、329、385页生成6组候选、8条精确来源。

## 二、两分钟介绍

上一阶段已经能追踪到资料版本、PDF页和具体提取工具结果，但一页里可能有几十条内容，所以来源还不够精确。我比较了四种切法：固定长度简单但会拆开故障项和安全警告；一页一段噪声太大；完全由模型切分不稳定且可能改写；结构规则能保留故障条目、阈值、复位条件和警告块，因此选择结构为主、长度为兜底。

数据库新增1开始、包含起点、不包含终点的字符范围以及逐字摘录。触发器使用保存的页面正文重新截取，和摘录不一致就拒绝。片段还记录切片方式、工具名称和版本；没有可复现切片证据的记录不能通过审核。通过审核时，机器原文必须等于所有来源按顺序用换行拼接的结果，来源编号必须从1连续。

协调助手不能传机器原文，只传页面提取编号和逐字摘录。服务会拒绝不存在的摘录，也会拒绝同一句在一页出现多次时猜位置；跨页或同页不相邻的多段证据可以按顺序组合。所有写入在一个事务中完成，并且状态固定为待审核。

实施中还发现旧唯一约束过严：同一页的两段不相邻证据无法同时挂载。我把唯一范围改成“片段 + 提取结果 + 起点 + 终点”，既允许不同范围，又继续拒绝重复范围。最终真实候选包覆盖OHF定义、阈值、手动复位、重启警告、禁用错误检测危险说明和不可复位故障处理步骤，没有一条被自动批准。

## 三、架构怎样讲

```text
官方PDF
  → 页级提取结果（工具、版本、正文指纹）
  → 协调助手或人工提出逐字摘录
  → 候选创建服务定位唯一位置
  → 数据库再次截取原页核对
  → 待审核知识片段（机器原文由来源拼出）
  → 工程师对照PDF审核
  → 后续向量和检索
```

两条核心原则：

1. 页面位置不能决定知识边界，业务目的和风险边界才能决定知识边界。
2. 模型负责建议“应该引用哪段”，程序证明“这段确实在原页”，人工决定“这段能不能进入正式知识”。

## 四、高频面试问题

### 1. 为什么不用固定500字切片？

固定长度不理解设备手册结构。它可能拆开故障代码与含义，也可能只保留重启操作而丢掉后面的未预期运行警告。固定长度可以在结构块超过模型输入上限时兜底，但不能先于安全和业务边界。

### 2. 为什么一页一个片段不行？

第72页同时有OHF、OLF、OPF等很多错误代码。一页一个向量会混入大量无关语义，精确问题返回的上下文也更长。页码是来源位置，不应直接等同于检索粒度。

### 3. 为什么不完全让大模型决定边界？

模型输出可能不稳定，还可能总结或漏掉警告句。我的设计允许模型提出候选，但服务逐字核对，数据库再次校验，最后由人工审核。这样既利用模型理解能力，又不把事实写入权交给模型。

### 4. 为什么接口不接受 `original_text`？

只要允许模型自由填写机器原文，它就可能引用第72页却写“冷却风扇已经损坏”，而手册原页并没有这个结论。机器原文应由验证过的来源摘录按顺序推导，不能成为自由输入。

### 5. 起止字符为什么不用字节位置？

中文字符在UTF-8里通常占多个字节，字节位置不适合审核人员理解。PostgreSQL `substring` 按字符位置工作，所以保存字符范围，起点从1开始，终点不包含，长度直接等于终点减起点。

### 6. 为什么既存起止位置又存摘录，不是重复吗？

起止位置便于回到原页高亮，摘录便于查询和审阅。它们不是各自随意变化：数据库触发器用位置重新截取并要求逐字等于摘录。这是带一致性校验的冗余。

### 7. 同一句出现两次怎么办？

服务拒绝使用第一个位置猜测，要求调用方提供更长的上下文，让摘录在页面中唯一。可复现性比“尽量导进去”更重要。

### 8. 为什么允许同一页出现两条来源？

第310页的复位前提和OHF适用列表不相邻，中间有不必要的终端说明。两段都需要，但不应把中间噪声全带入，因此保存两个不同范围。相同范围重复保存仍被唯一约束拒绝。

### 9. 为什么来源顺序必须从1连续？

机器原文由来源顺序拼接。如果出现1、3而没有2，无法判断是漏数据还是编号错误。审核通过前强制连续，可以确保重放结果唯一。

### 10. `source_severity` 和 `usage_policy` 为什么不能合成一个风险字段？

第385页候选把原文危险等级建议为普通说明，把系统用途建议为工程师专用。这个候选说明一个字段无法同时表达“原文怎样标注”和“系统允许怎么用”。两项当前都只是待审核建议，最终专业结论由领域工程师确认，不由 FDE 或模型冒充确认。

### 11. 第50页的 `1 18%` 怎么处理？

机器提取原文保留 `1 18%`，不能静默改写。候选保持待审核，工程师对照PDF视觉内容后，可以把核对正文保存为 `118%`，两份文字同时保留。这能区分提取事实和人工修正。

### 12. 为什么所有候选仍是待审核？

切片程序只能证明摘录确实存在，不能证明分类正确、文字提取无误或工业使用安全。尤其阈值和高危步骤必须人工复核。候选创建和批准是两个独立权限。

### 13. 旧库为什么不自动回填范围？

一页可能有重复句子，旧片段也可能跨多个不相邻范围。按第一次字符串匹配自动回填会制造看似精确的假证据。迁移明确阻断，让人工提交边界清单。

### 14. 哪些真实产品支持你的选择？

Amazon Bedrock 知识库公开提供固定、父子层级和语义切片；Microsoft Azure AI Search 公开提供固定、按结构、语义和组合切片，并保留父级来源；Docling 先按文档层级切，再按模型长度拆分或合并。它们证明结构切片和组合策略有真实产品背景，但本项目的安全分类、表结构和审核门禁是针对工业维修场景自行设计的。

### 15. 你怎样验证不是只写了文档？

自动测试覆盖数据库逐字匹配、范围合法性、提取状态、切片版本、审核门禁、机器原文重建、连续顺序、迁移阻断、摘录缺失、重复句、跨页、同页多范围和真实候选包。真实测试导入440页提取物，6组候选的8条摘录都必须在指定页面唯一出现，最终批准数必须为0。

### 16. 作为 FDE，你需要判断设备维修结论吗？

不需要。我的职责是把模型建议、官方证据、确定性校验、专业审核和运行权限分开：模型提出完整候选，程序证明引用真实存在，领域工程师确认设备含义和安全性，数据库保存审核记录，运行时只使用已批准知识。系统不能因为 FDE 不懂某台设备，就退化为让模型自行批准；也不能把专业判断题转嫁给 FDE。

## 五、真实问题和修复过程

### 问题一：旧唯一约束挡住同页多范围

现象：第310页两段不相邻证据写入第二段时触发重复提取结果错误。

原因：上一阶段还没有页内范围，只能把“同一提取结果”当作重复。新增范围后，判重粒度应该下沉到具体区间。

修复：先用 R111 重现失败，再把唯一约束改为片段、提取结果、起点、终点四列组合。旧 R84 继续证明同一范围不能换顺序重复添加。

### 问题二：模型编造的摘录直到数据库才报错

现象：初版服务对找不到的文本计算出0起点，最后得到不直观的数据库错误。

修复：R107先要求清楚的“页面中找不到摘录”错误，再在写入前显式检测；事务仍作为最后回滚保障。

### 问题三：重复句会被默认定位到第一处

现象：普通查找会自然返回首次出现位置，但无法证明这是调用方想要的位置。

修复：R108要求出现多次时拒绝，并让调用方扩展上下文到唯一摘录。
