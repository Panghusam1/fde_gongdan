# 阶段二十一：数据库状态绑定与已暴露缺陷回归

## 30秒项目介绍

“端到端未见测试发现协调模型会把第一版依据写成空值，也会填写错误的风险和证据编号。我没有继续堆提示词，而是重划系统边界：模型只生成业务方案，程序从当前工单状态绑定所有数据库内部编号，数据库再做权限和证据约束。三个已暴露故障用真实 E5、千问和数据库回归 3/3；旧的 5/12 失败报告保留，下一步必须换新未见数据验证推广。”

## 面试问题：为什么不能要求模型照抄编号？

照抄仍然是概率行为，而数据库身份和权限必须是确定行为。模型输出可能为空、过期或幻造；错误编号轻则请求失败，重则把一个工单的操作指向另一条记录。因此内部编号不是自然语言推理内容，而是应用状态，必须由程序绑定。

## 面试问题：怎样避免只在模型适配器里修补？

做两层保护。千问适配层先规范化输出，使旧的严格参数解析器能继续工作；新版工具编排层在执行前再次读取当前工单上下文并覆盖主键。R274 故意让测试模型填写不存在的风险号和证据号，最终数据库仍创建第一版方案且只引用当前已批准证据。

## 面试问题：为什么回归通过后不能说准确率提升到100%？

E201、E202、E205 的结果已经暴露，代码也针对这些故障修改过，所以 3/3 只能证明缺陷回归通过。它不能估计新问题上的推广效果。完整首跑仍是 5/12 失败；下一轮要在修改完成后封存全新的问题和标准，再首次运行。

## 面试问题：四条数据问题如何处理？

不覆盖旧标签和报告。E203、E204 含厂家原文未支持的额外限制；E206、E207 的输入是操作指令，不符合“资料能否回答问题”的测量形式。项目另存裁决记录，把它们移出未来未见准确率分母，并用清楚问题重新建新样本。

## 权威资料与权威边界

- Schneider Electric 的 NVE41300 是产品厂家发布的一手资料，对“手册写了什么”有权威性；它不批准本项目自定的风险等级，也不代替现场工程师。
- NIST AI RMF 是由美国国家标准与技术研究院通过公开协作形成的风险管理框架，对测试、评价、验证和记录方法提供规范性参考，但不为本项目结果背书。
- Google《机器学习规则》来自其工程团队的一手实践，支持分开测试基础设施、保持整链稳定和使用后续新数据；它是工程经验，不是工业安全标准。
