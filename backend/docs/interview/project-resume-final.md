# FDE项目简历定稿：工业售后智能工单系统

## 项目名称

工业设备售后智能工单与可信知识检索系统

## 项目角色

FDE / AI应用工程师：负责业务流程梳理、数据与知识架构、模型接入、安全边界、自动化评测和可演示交付。

## 简历四条版

- 面向设备生产、组装与维修厂商，从零设计单协调助手工单系统，覆盖厂区与型号确认、草稿工单、现场观察、官方资料检索、证据判断、风险阻断、最多两版方案、现场确认和人工接管，并以状态机、窄工具和数据库约束限制模型越权。
- 基于 TypeScript、PGlite/PostgreSQL、pgvector 和 `multilingual-e5-small` 建立可信知识链，导入一份440页、约6.3MB的厂商手册，记录文件 SHA-256、资料版本、逐页提取、精确字符范围、人工审核和不可变事件；40题检索复测中 E5 前三命中100%，同时如实保留首位76.7%的不足。
- 接入真实 `qwen3.7-plus` 进行协调决策与证据判断，建立首跑前数据和代码散列封存、已暴露回归与真实状态登记；20案例40轮协调评测结构输出100%、动作与参数92.5%，全新12条端到端工单达到11/12且五条安全分支5/5。
- 针对三批来源身份未见失败，将资料编号、版本和语言从自由文本中拆为人工确认的结构化字段，由数据库在模型前精确过滤；第四批真实未见11/12，五条无匹配来源全部零模型调用阻断，错误来源接收0、判断异常0。
- 将本地演示封装为受控 HTTP 服务并接入独立 Next.js 多工单运营台；后端提供覆盖六阶段的13条项目评测记录，从页面真实跑通正常闭环、高危阻断、证据不足、未授权厂区和来源不匹配五条路径；将证据存在性收口到后端结构化状态，确保只有通过证据门的工单可以展示官方手册页码、图片和原文。

## 简历两条精简版

- 设计并交付工业设备售后智能工单系统，以单协调助手、状态机、窄工具和 PostgreSQL 约束跑通官方资料检索、证据判断、风险阻断、两版方案及人工接管；构建440页厂商手册的版本化、页级和逐字来源链。
- 建立 E5 + 关键词检索、真实千问判断和首跑前封存评测体系；从三批未见失败定位提示词来源校验缺陷，重构为数据库结构化来源过滤，第四批未见11/12、来源不匹配阻断5/5、错误来源接收0。

## 30秒项目介绍

这是一个给设备生产和维修厂商使用的售后工单系统。现场确认厂区和型号后立即建单，系统持续记录现象，检索当前有效官方资料，判断证据和风险，再生成最多两版完整方案；高危、来源不匹配、证据不足或两版失败都转人工。架构上只有一个协调助手，模型负责语义判断，数据库和程序负责身份、权限、状态和风险边界。项目使用真实厂商手册、E5和千问，并通过未见数据和数据库终态验证，不只演示聊天效果。

## 技术栈

- TypeScript、Node.js；
- PGlite，本地开发兼容 PostgreSQL；
- pgvector；
- `multilingual-e5-small`；
- 百炼 `qwen3.7-plus`；
- PDF逐页提取、SHA-256、版本化知识审核；
- Node原生测试、内存数据库、首跑前散列封存。
- Next.js 静态展示站、Node.js 独立演示接口、浏览器跨域控制。

## 最能体现FDE能力的三点

### 1. 把业务语言变成可执行边界

“高危转人工”“最多两版”“确认厂区和型号后立即建单”都被转换为状态、约束、工具许可和自动化测试，而不是只写在提示词里。

### 2. 用失败数据推动架构调整

没有用已暴露12/12包装成功。三批新来源题两次出现错误放行后，停止继续补提示词，把来源身份改为结构化确认和数据库过滤。

### 3. 区分演示、项目评测和生产能力

离线演示证明流程可重放；首次未见报告证明项目题上的模型效果；领域审核、真实工单和正式 PostgreSQL 负载仍明确列为外部验证项。

- “维修方案通过施耐德工程师认证”——尚无领域专家审核；
- “支持生产级高并发”——尚未迁移正式 PostgreSQL 做负载测试；
- “检索准确率100%”——只能准确写 E5 前三命中100%，首位为76.7%；
- “防住所有提示攻击”——只能写第四批项目自建来源题错误接收0；
- “多智能体系统”——项目是单协调助手加受控能力组件。

## 关键面试句

> 页面位置不能决定知识边界，业务目的和风险边界才能决定知识边界。

> 确定性的业务身份交给程序和数据库，需要语义理解的内容关系才交给模型。

> 回归通过只能证明已知问题被修复，新的能力必须用首次运行前封存的未见数据验证。
